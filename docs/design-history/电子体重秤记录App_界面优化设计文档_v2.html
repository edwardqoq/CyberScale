01项目背景与目标

Project Background & Goals

本次工作针对一款电子体重秤记录 App 的 base 版本界面做整体优化。原稿共 4 张主界面（动态 / 趋势 / 历史 / 我的），四页均停留在「暂无数据」的空状态，属于典型的开发占位稿，尚不具备可评审的视觉与信息层级。

设计目标

  • 建立一套统一、专业、可信赖的健康数据视觉语言，替代原稿零散的高饱和色块。
  • 把「测量」这一核心动作从不可见的文字提升为四屏一致的主操作。
  • 补齐图表、记录流与统计信息，让界面在真实使用中具备完整的信息架构。

设计范围：4 个主界面，设计基准 390 × 844 pt @1x，交付导出 @2x（780 × 1688 px）。

02原版问题诊断

Audit of the Base Version

以下 7 项是本次优化的主要依据，按对用户体验的影响程度排序。

#原版问题带来的影响本次处理
1四屏全部为「暂无数据」空状态新用户首次进入即面对空白，产品价值与下一步动作均不可感知改为「有真实数据的理想态」；空态版本列为后续专项
2顶部高饱和青色条视觉压迫感强，与健康管理类产品需要的克制、可信赖气质不符改为暖白底 + 深蓝渐变主卡，主色收敛为单一品牌蓝
3「测量」为右上角纯文字产品的核心主操作几乎不可见，首屏转化路径断裂升级为四屏一致的深蓝渐变胶囊主按钮，含「+」图标
4仪表盘四色分段且无图例颜色语义不明，用户无法判断落在哪个区间代表什么改为单色薄荷绿进度环 + 环心大数字 + 明确状态标签
5黄 / 青纯色卡片信息层级扁平，文字对比度不足，长时间阅读疲劳统一为白卡 + 细描边，仅对关键数字着色
6底部图标风格不统一，选中色与顶栏脱节导航识别弱，四个 Tab 缺乏一致的状态语言统一线性图标 + 浮动胶囊容器，激活项实心深蓝
7趋势 / 历史页无图表、无记录数据类产品最核心的「变化」无法被看见补齐折线图、柱状图、统计概览与月度记录流

03设计策略

Design Principles

01　统一视觉语言以「清爽、专业、可信赖」为基调：暖白画布承载信息，深蓝只在主操作与 Hero 上出现，薄荷绿只表达「向好」的数据状态。
02　让数据自己说话颜色不用于装饰，只用于状态与关键数值；每一屏都能回答一个明确问题，避免「为了好看而堆卡片」。
03　以理想态评审本次刻意使用带示例数据的理想状态，使信息架构、图表层级、涨跌语义可被评估；示例数据非真实业务数据。
⚠　文档与视觉稿中的 62.4 kg、24 次测量、68% 进度等均为示例数据，用于校验版式与数据语义，不代表真实业务数据。

05全局框架与组件规范

Layout System & Components

5.1　页面结构

四屏采用完全一致的纵向骨架：状态栏 62 pt → 内容区（弹性，左右边距 20 pt、卡片间距 14 pt）→ 浮动胶囊导航 96 pt。内容区不足一屏时不做拉伸，超出时纵向滚动；底部导航始终浮于内容之上。

08待确认事项与后续建议

Open Questions & Next Steps

待确认理想态 vs 空态
本次为便于评审采用带示例数据的理想态。若需要 base 版空状态优化稿，建议另出一版「优雅空态」，含引导测量插画与首启文案。

建议深色模式
深蓝渐变主卡在深色下需重新定义明度，白卡替换为 #151B26 层级，语义绿提亮至 #34D399。

建议无障碍
当前弱文字 #9AA3B2 对白底约 2.6:1，正文建议提升至 #6B7280 以上；核心数字支持系统字号放大不截断。

建议图表交互态
补充长按查看某日数值的浮层、周/月/年切换后的图表过渡、无数据周的占位样式。

建议单位与本地化
预留 kg / lb 切换、日期格式与多语言文案长度对版式的影响。

建议工程落地
把本文色彩与字号导出为 Design Token，组件按 5.2 清单建立组件库，减少后续页面漂移。

⚠　需要你确认：本次交付的是「有数据的理想态」。如果你要的是 base 版空状态的优化稿，请告知，我会基于同一画布另出一套「优雅空态」版本，补上引导测量插画与首启文案。
